Javaテストの現実
テストコードはビジネスロジックと同じくらい重要な設計成果物なので、自動生成するものではありません。何を検証すべきかは人間が考える必要があります。

今回作ったテストを業務で再利用する場合の手順
今回の SalesDocumentHandlerTransactionTest.java の構造をテンプレートとして使えます。


1. テストクラスを作成
   @SpringBootTest
   class XxxHandlerTransactionTest { ... }

2. テスト対象ハンドラを @Autowired

3. 正常系・異常系のテストメソッドを @Test で追加

4. @AfterEach でテストデータをクリーンアップ
一部を補助してくれるツール
ツール	できること
IDE（VSCode/IntelliJ）	テストクラスの雛形生成（クラス名・メソッド名の骨格のみ）
GitHub Copilot / AI	テストコードの提案（中身も含む）
JUnit	テストの実行・結果表示
ただし、「何を検証するか」「どんなデータを使うか」は人間が決める必要があります。今回のように「詳細INSERT失敗時にヘッダ・明細もロールバックされるか」という観点は、設計を理解していないと書けません。
